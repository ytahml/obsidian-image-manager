# 05 — 支持连续操作、多图与上传竞态的失败关闭

**What to build:** 让 delegated 自动接力在多图、连续粘贴、持续编辑、编辑器生命周期变化和网络竞态中保持事务隔离；能够确定的项目继续完成，无法确定的项目独立失败且不产生错误写入或删除。

**Blocked by:** 04 — 打通单图 delegated 自动图床接力。

**Status:** ready-for-agent

- [ ] 每次 paste/drop 建立独立事务，每张输入图片形成独立项目并分别汇总成功、取消和失败。
- [ ] 无关编辑不重置收敛；候选文件、目标引用或唯一映射变化时重新求解。
- [ ] 同一来源笔记可并行观察多个事务，但引用重定位和替换写入串行。
- [ ] 已达到可接力状态的项目最多两项并发上传，并在各自上传前后独立重验。
- [ ] 相同字节、重复文件名、相同引用和事件乱序不能按哈希、basename 或临近时间强行配对。
- [ ] 切换活动笔记不迁移事务；关闭 Editor 后只有已保存内容能唯一恢复时才继续。
- [ ] 来源笔记或附件删除、关闭自动上传、切回 managed 或插件卸载会安全取消适用事务；重载不恢复旧事务。
- [ ] 上传请求在途期间发生相关变化时，结果不可替换或删除；不自动二次上传，也不自动删除未采用的远端对象。
- [ ] 每次网络重试前重验指纹；设置变化后不得继续使用过期策略或静默切换图床。
- [ ] 每个事务最多一条脱敏汇总；上传已完成但结果未采用时说明本地已保留且远端可能有未引用对象。
- [ ] 确定性测试覆盖多图部分成功、连续事务、持续编辑、编辑器关闭、设置取消、卸载和在途结果失效。
- [ ] canonical 文档同步边界与“部分实施”证据。
- [ ] `npm test`、`npm run build` 和 `git diff --check` 通过。
