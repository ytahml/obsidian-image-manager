# 08 — 完成跨切片自动化集成验证

**What to build:** 将本地管理模式、委托事务、压缩授权、rename 协作和安全本地回收作为一条完整生命周期进行自动化验证，证明各独立切片组合后仍保持 managed 回归、失败关闭和双版本设置一致性。

**Blocked by:** 06 — 协调外部 rename 修复与显式本地修改；07 — 保护状态未定图片与安全本地回收。

**Status:** ready-for-agent

- [ ] 通过单一生命周期测试缝输入标准化 Obsidian、Editor、Vault、设置、上传和时钟事件，验证外部效果而非私有状态。
- [ ] 模拟 Obsidian 默认行为和第三方附件管理器的 create/modify/rename/reference 事件序列与乱序。
- [ ] 覆盖延迟与连续 rename、引用先后顺序、阻塞队列、连续粘贴、多图、重复名称/字节和用户持续编辑。
- [ ] 覆盖 managed/delegated、自动上传开关、Markdown/Wiki、上传成功/失败/超时、配置漂移和本地副本开关。
- [ ] 证明过期上传结果不会替换引用、删除本地文件、自动重传或静默切换图床。
- [ ] 证明 rename 修复与状态未定孤立保护在完整事务中按事件边界协作。
- [ ] 验证所有旧设置迁移组合，以及 Obsidian 1.13 声明式设置与 1.12 fallback 的中英文等价行为。
- [ ] 所有错误和通知脱敏，事务级通知数量符合契约。
- [ ] 测试不使用真实等待；200ms、800ms、两秒和 30 秒均由假时钟驱动。
- [ ] `npm test`、`npm run build` 和 `git diff --check` 全部通过。
- [ ] canonical 文档记录自动化覆盖范围和仍待真实环境验证的边界，状态保持“部分实施”。
