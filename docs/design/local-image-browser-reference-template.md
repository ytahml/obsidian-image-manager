# 本地图片浏览器与上传引用模板增强

> 状态：实施中
> 关联分支：`feat/image-browser-reference-template`

## 背景

远程图床视图已经提供带语义颜色的引用状态和受保护的孤立图片删除，本地视图此前只有孤立按钮，没有完整引用状态筛选、卡片状态或浏览器内删除。上传后的自定义引用模板也只公开 `{fileUrl}`、`{fileAlt}`，且“无效模板”只有缺少 URL 的隐式规则。

## 目标

1. 本地卡片显示绿色“已引用”、橙色“孤立图片”，引用扫描失败时保守显示灰色“无法判断”。
2. 在本地浏览器多选孤立图片并移入 Obsidian 配置的回收站；删除不信任旧扫描结果。
3. 为上传后引用增加稳定的文件名、扩展名和固有像素尺寸变量。
4. 冻结由设置页和运行时共同执行的严格模板有效性契约。

## 非目标

- 不把本地引用检测切换为远程 URL 引用索引，也不扩大到非 Markdown 文件。
- 不永久删除本地图片、不清理父目录、不增加删除历史。
- 不改变本地粘贴、Markdown/Wiki 转换、重命名或资源整理的引用格式。
- 不校验用户模板的 HTML、Markdown 或 CSS 语法。
- 批量上传只上传文件，不生成引用，因此不消费自定义引用模板。

## 用户流程与交互

### 本地浏览与删除

1. 打开本地图片视图后立即显示图片，同时异步扫描 Markdown/Wiki 引用。
2. 扫描期间卡片显示“正在检查引用”，引用状态筛选和删除不可用。
3. 扫描成功后显示“已引用”或“孤立图片”；只有孤立卡片显示选择控件。
4. 引用扫描成功后可在“全部引用状态 / 已引用 / 孤立图片”间筛选；选择跨搜索、排序、引用状态筛选和卡片重绘保留，底部显示数量与总大小。
5. 点击删除时先重新扫描并更新选择；确认后再次扫描，只把仍存在且仍为孤立状态的项目逐项交给 `fileManager.trashFile()`。
6. 结果分别报告已移入回收站、因状态变化跳过和失败数量，然后刷新图片与引用状态。

任何一次引用扫描失败都不得把图片标为孤立；视图显示“无法判断”并禁用筛选和删除。

### 自定义引用模板

| 变量 | 值 |
|------|----|
| `{fileUrl}` | 上传后的可读 URL，必填 |
| `{fileAlt}` | 当前引用 alt；没有现有引用时为文件名主干 |
| `{fileName}` | 源文件完整名称 |
| `{fileBaseName}` | 源文件名主干 |
| `{fileExt}` | 不含点号的小写扩展名 |
| `{fileWidth}` | 固有像素宽度，正整数 |
| `{fileHeight}` | 固有像素高度，正整数 |

只有结构有效且实际使用宽高变量的模板才读取图片尺寸。尺寸读取失败不改变上传结果，但该次引用回退到默认 Markdown。

## 模板有效性契约

- 空白模板表示关闭自定义模板，不属于错误。
- 非空模板必须包含 `{fileUrl}`。
- `{identifier}` 形式的未知变量使模板无效；普通文本和其他花括号原样保留。
- 使用 `{fileWidth}` 或 `{fileHeight}` 时，相应值必须可取得且为正整数。
- 有效变量可重复出现，替换值按普通文本处理，不解释 `$&` 等替换序列。
- 无效模板在设置页即时提示但仍可保存草稿；运行时统一回退为 `![alt](url)`。

## 技术设计

- `reference-template.ts` 统一占位符解析、结构验证、按需尺寸元数据读取和渲染，设置页与上传入口不各自实现规则。
- 直接上传、笔记上传、上传后替换和粘贴自动上传在成功后生成同一份文件元数据；替换同一文件的多个引用时复用该元数据。
- `local-orphan-management.ts` 提供引用状态映射、选择校验和二次扫描后的顺序回收站删除；图片浏览器与旧孤立图片 Modal 共享该边界。
- 本地视图使用 generation 隔离切换页签或关闭后迟到的扫描结果。

## 安全、隐私与性能

- 删除始终使用当前 Vault 的新扫描结果；新增加引用、文件消失或不再孤立的项目被跳过。
- 本地删除使用 Obsidian 配置的系统回收站或 Vault `.trash`，不调用永久删除和目录清理。
- 尺寸仅在模板使用宽高时读取，每张成功上传的图片至多读取一次；读取失败被限制在引用生成阶段。
- 新变量不公开 Vault 路径、笔记路径或其他额外隐私信息。

## 测试矩阵

- 模板：全部变量、重复变量、特殊替换字符、空白、缺少 URL、未知变量、普通花括号、尺寸缺失和按需尺寸读取。
- 本地管理：扫描中/成功/失败状态、只能选择当前孤立项、文件消失或新增引用后的跳过、部分回收站失败。
- 上传回归：直接上传复制、自动替换、笔记上传和粘贴自动上传的 alt 与文件元数据一致；批量上传不变。
- 人工验收：桌面端和移动端标签、搜索/排序/筛选、跨重绘选择、二次确认、实际回收站位置，以及有效/无效 HTML 模板输出。

## 验收标准

- 本地卡片引用状态与远程卡片使用一致的绿色、橙色和灰色语义。
- 没有新鲜孤立扫描结果时不存在可执行的本地删除入口。
- 确认后新增引用的图片不会被删除，失败项不会从 Vault 列表中错误移除。
- 所有已声明变量在四条引用生成路径中具有相同语义；无效模板可靠回退 Markdown。
- `npm test`、`npm run build` 和 `git diff --check` 通过，并完成真实 Obsidian 人工验收。
