# Issue #36 本地图片生命周期委托与图床接力执行规格

> 状态：已确认
> 说明：本文是 canonical 设计文档的派生执行规格；发生冲突时，以 `docs/design/issue-36-local-image-workflow-ownership.md` 为准。本文仅保存在本地仓库，不替换或评论用户原 GitHub Issue。

## Problem Statement

用户可能只希望使用 Image Manager 的图床能力，同时继续由 Obsidian 或 Attachment Management 等插件管理本地附件。当前 Image Manager 会拦截 Markdown 编辑器中的图片粘贴和拖放，自行创建、命名、放置、压缩本地图片并插入引用，还可能立即开始自动上传；其他附件管理者随后也可能移动、重命名同一文件并更新同一引用。

Issue #36 没有稳定的用户复现步骤，因此本需求不是对某个已复现 bug 的修复。它要优化本地图片生命周期中的职责划分和协作方式，降低多个插件同时处理新附件时的竞争风险，并让用户能够在让渡本地管理权后继续使用安全、可验证的自动图床接力。

## Solution

将“谁管理本地附件”和“是否在粘贴后自动上传”拆成两个正交设置：

- 本地管理模式为 `managed` 或 `delegated`。
- 粘贴后自动上传独立开启或关闭。

`managed` 保留 Image Manager 当前对 Markdown paste/drop、本地命名、路径、可选本地压缩和初始引用的所有权。`delegated` 不阻止 Obsidian 默认行为，也不创建、命名、移动或修改本地附件；自动上传开启时，插件只观察本次事务产生的候选文件和新增引用，在两者达到可验证的可接力状态后执行上传，并只替换本次事务的精确引用。

通用协作仅依赖 Obsidian 公开的 editor、Vault 和链接解析状态，不依赖 Attachment Management 的插件 ID、内部队列或私有完成协议。歧义、超时、设置漂移、上传期间状态变化或删除资格不确定时全部失败关闭，保留本地文件和引用。

## User Stories

1. 作为 Image Manager 用户，我希望选择由本插件还是其他附件管理者拥有新本地图片的管理权，以免两个插件竞争处理同一附件。
2. 作为现有用户，我希望升级后保留原有的有效粘贴和上传行为，以免版本更新静默改变仓库。
3. 作为 managed 用户，我希望本插件继续处理 paste/drop，以保持现有命名和路径流程。
4. 作为 delegated 用户，我希望由 Obsidian 或其他插件创建和整理本地附件，使外部命名与放置策略保持权威。
5. 作为 delegated 用户，我希望本插件不阻止 paste/drop 默认行为，使附件管理者能接收正常的 Obsidian 生命周期。
6. 作为用户，我希望自动上传独立于本地管理权，以便自由组合本地与远程工作流。
7. 作为关闭自动上传的 delegated 用户，我希望本插件不建立粘贴事务，以免产生无收益的跟踪。
8. 作为开启自动上传的 delegated 用户，我希望新引用唯一解析到最终附件后才上传，以免使用过期路径。
9. 作为粘贴后继续输入的用户，我希望无关编辑不延迟自动上传，使正常编辑保持流畅。
10. 作为修改或删除新图片引用的用户，我希望事务安全重算或取消，以免替换错误文本。
11. 作为切换笔记的用户，我希望事务继续绑定来源笔记，而不是错误跟随活动编辑器。
12. 作为关闭来源编辑器的用户，我希望只有保存内容能唯一恢复目标引用时才继续，以免修改未保存或歧义内容。
13. 作为卸载或重载插件的用户，我希望未完成事务被取消而不是恢复，以免过期内存上下文稍后修改仓库。
14. 作为一次粘贴多张图片的用户，我希望每个图片项独立成功或失败，使一项歧义不阻塞其他有效项。
15. 作为连续粘贴的用户，我希望每次事务保持隔离，使后一次粘贴不能捕获前一次文件或引用。
16. 作为粘贴相同字节或文件名的用户，我希望歧义失败关闭，以免插件按哈希或 basename 猜测。
17. 作为 delegated 用户，我希望上传压缩只影响上传载荷，以免本插件修改其他管理者拥有的附件。
18. 作为 managed 用户，我希望分别配置本地粘贴压缩和上传载荷压缩，使本地与远程存储策略相互独立。
19. 作为用户，我希望两个模式都保留显式重命名、整理和本地压缩命令，使委托不会移除主动工具。
20. 作为 delegated 用户，我希望显式本地修改说明外部策略风险，以理解其他插件可能撤销或响应这些修改。
21. 作为外部附件管理器用户，我希望其更新引用期间本插件延后 rename 修复，以免双方并发写同一引用。
22. 作为关闭 Obsidian 内部链接自动更新的用户，我希望保留保守的断链修复，以维持历史安全能力。
23. 作为经历大量 rename 的用户，我希望修复被批处理并使用 Obsidian 语义判断链接有效性，以免重叠全库扫描和 basename 猜测。
24. 作为浏览孤立图片的用户，我希望活跃或近期变化的图片显示为状态未定，以免瞬态状态启用删除。
25. 作为删除孤立图片的用户，我希望确认和执行时都重新扫描，使只有仍被证明孤立的图片进入回收站。
26. 作为关闭本地副本保留的用户，我希望精确替换且全库无本地引用后才删除，以免移除共享附件。
27. 作为用户，我希望自动替换只覆盖本次事务创建的精确引用，以免静默修改复制到其他位置的引用。
28. 作为上传期间附件发生变化的用户，我希望上传结果不能用于替换和删除，以免在途请求应用过期状态。
29. 作为过期上传已在远端完成的用户，我希望收到可能存在未引用对象的提示，以便手动检查。
30. 作为用户，我希望事务失效后不自动删除远端对象或重新上传，使远端副作用保持保守可理解。
31. 作为用户，我希望每个 paste/drop 事务最多一条汇总通知，以免内部事件重验造成提示轰炸。
32. 作为主动删除目标引用的用户，我希望取消保持静默，使预期编辑不会产生错误提示。
33. 作为配置 delegated 的用户，我希望 managed 专属设置被禁用并解释而非清除，使切换回来仍保留选择。
34. 作为用户，我希望解析到启用图床后才能开启自动上传，以免每次粘贴都进入必然失败的流程。
35. 作为事务中途修改设置的用户，我希望事务保持一致配置快照且不静默更换图床，使一次操作不会混用策略。
36. 作为 Markdown 用户，我希望首版支持 delegated paste 和桌面 drop，以覆盖最可靠的编辑器工作流。
37. 作为 Canvas 用户，我希望发布说明明确 Canvas 不支持自动接力，以免误以为存在不安全的来源猜测。
38. 作为移动端用户，我希望只声明真实移动端环境已验证的能力，以免文档过度承诺。
39. 作为维护者，我希望使用 Attachment Management 0.12.1 固定基线进行真实验收，使兼容结论可复核且有证据边界。
40. 作为维护者，我希望将本功能描述为生命周期协作增强而不是已复现 bug 修复，使 Issue、PR 与发布说明符合证据。

## Implementation Decisions

- 本地管理模式只有 `managed` 与 `delegated`；不持久化 `off`，`delegated` 加关闭自动上传即为完整 paste/drop 退出。
- 自动上传保持独立布尔值；delegated 关闭自动上传时不创建事务、候选收集器或收敛计时器。
- 将 managed 粘贴引用格式与显式整理转换拆开；图床配置、手动上传和自动上传不再由二者门控。
- 将自动压缩拆为 managed 本地粘贴压缩和上传载荷压缩，共享质量；显式覆盖压缩保持独立命令。
- 旧安装迁移为 managed；新自动上传值由旧有效门控和能否解析启用图床共同决定，迁移不联网验密。
- 建立一个高层生命周期协调器作为主要行为测试缝，接收标准化 paste/drop、Editor、Vault、设置与时钟事件，输出上传、精确替换、通知、修复延后和本地删除资格等效果。
- Obsidian 事件注册和效果执行保留在适配边界；复用现有上传服务，并在引用/孤立服务中统一 Obsidian 链接解析语义。
- 每个 paste/drop 事件是一项事务，内含独立图片项；事务绑定来源笔记而非活动编辑器。
- 事务仅存在内存；插件卸载时取消，重载后不恢复。
- 可接力状态要求输入项、最终 `TFile` 身份和精确新增引用形成唯一映射，不判断变更行为人。
- 无关笔记编辑不影响事务；候选文件、目标引用或唯一映射变化时重算；目标引用删除时取消，无法唯一恢复时失败关闭。
- 强收敛缓冲 200ms，弱收敛缓冲 800ms；从 paste/drop 开始设置不可延长的 30 秒硬超时。这些是可注入内部常量，不是用户设置。
- 强收敛要求观察到文件 move/rename，随后引用跟随并唯一解析到最新文件；弱收敛只有唯一初始映射，没有后续跟随证据。
- 允许并行观察事务和最多两项并发接力上传；同一来源笔记的引用重定位、替换和本地回收写入串行。
- 每项事务快照图床 ID、上传压缩、引用模板和本地副本策略；上传前验证快照图床仍启用，绝不把在途事务改投其他图床。
- 每次上传尝试前、上传后和替换前重验事务指纹；请求在途期间的相关变化使结果不可用于替换或删除。
- 不自动重新上传变化后的项目，也不自动删除未采用的远端结果；事务结束时统一报告。
- delegated 自动接力只替换事务精确引用，不扫描扩大到同一本地文件的其他引用。
- 关闭本地副本保留时，精确替换后执行完整本地引用扫描；只有无本地引用且指纹仍有效时才送入回收站。
- 活跃事务文件以及最后相关 move/rename/reference 变化后两秒内的文件标记为状态未定，不可分类、选择或删除为孤立；确认和执行时继续复扫。
- 委托事务内的外部 rename 延后修复；结果引用可解析时不修复，保护后仍断链才使用 Obsidian 解析语义保守修复；非事务 rename 也批处理。
- delegated 保留显式重命名、整理和覆盖压缩；在既有交互界面提供针对性风险提示，不增加通用警告层。
- 设置页分为本地附件管理与图床接力；delegated 禁用并解释 managed 专属控件，同时保留值。
- 无法解析启用图床时不能开启自动上传；自动上传关闭时隐藏或禁用本地副本控件。
- Obsidian 1.13 声明式设置与 1.12 imperative fallback 在顺序、验证、迁移和国际化上保持一致。
- 首版 delegated 自动接力只支持 Markdown 编辑器；桌面支持 paste/drop，移动端仅在宿主提供同等事件与文件数据时支持 paste；Canvas 排除。
- 每个事务最多一条汇总；主动删除引用导致的取消保持静默；所有失败脱敏，不显示响应正文、凭据、预签名 URL 或敏感 query。
- 按依赖顺序交付：设置与迁移、协调器提取并保持 managed、delegated 事务、rename/orphan 安全联动、自动化与真实验收、证据限定文档。
- Image Manager 单独运行及与 Attachment Management 0.12.1 的真实桌面验收完成前，不得标记功能完成。

## Testing Decisions

- 只通过一个主要生命周期测试缝验证协调器外部行为，不断言私有状态字段；输入标准化事件，验证上传、替换、取消、通知、修复和删除效果。
- 注入假时钟，使 200ms、800ms、两秒近期变更保护和 30 秒超时在测试中确定且无需真实等待。
- 复用现有 UploadService 测试作为 Provider 无关上传编排与重试先例。
- 复用笔记图片和上传引用测试作为 Obsidian 本地解析与安全替换先例。
- 复用本地孤立管理测试作为确认/执行复扫与 trash-only 删除先例。
- 复用远程会话测试作为 generation 隔离、迟到结果拒绝、受限并发、停止行为和请求注入边界先例。
- 覆盖旧自动上传、旧 Markdown/hosting 门控和可解析启用图床的全部迁移组合。
- 添加 managed 回归测试，证明提取后 paste/drop 所有权、命名、路径、本地压缩和自动上传行为不变。
- 添加 delegated 协调器测试，覆盖强/弱收敛、无关/相关编辑、引用删除、编辑器切换/关闭、来源删除、插件卸载、超时和设置取消。
- 添加多项与多事务测试，覆盖部分成功、相同字节、重复名称、相同引用、事件乱序和同笔记串行写入。
- 添加上传竞态测试，证明过期在途结果不能替换引用、删除本地文件、静默按新状态重试或切换图床。
- 添加 rename 修复测试，覆盖事务内抑制、引用可解析时不操作、批处理 fallback、内部链接自动更新开关和 Obsidian linkpath 语义。
- 添加孤立安全测试，证明活跃及两秒近期变化文件在展示、确认和执行边界均为状态未定。
- 在可行处覆盖设置 UI 等价性，并手动验证 Obsidian 1.13 声明式与 1.12 fallback 的中英文界面。
- 提交前运行 `npm test`、`npm run build` 和 `git diff --check`。
- 在真实 Obsidian 桌面环境中分别验证 Image Manager 单独运行和与 Attachment Management 0.12.1 同时运行，覆盖模式、内部链接自动更新开关、Markdown/Wiki、paste/drop、单图/多图、重复名称与字节、特殊字符、笔记驱动整理、成功/失败/超时、编辑器生命周期、插件卸载、本地副本和近期变更孤立扫描。
- 未在真实支持环境执行时将移动端标记为未验证；单元测试不能替代移动端或 Canvas 验收。

## Out of Scope

- 复现或声称修复某个确定的 Issue #36 bug。
- 针对 Attachment Management 私有队列、ID 或实现时序的运行时集成。
- 保证兼容所有附件管理插件。
- 持久化本地管理 `off` 值。
- Canvas 自动图床接力。
- 移动端 drag/drop 和任何未在真实环境验证的移动能力。
- 自动替换来源事务之外的引用。
- 自动删除未采用的远端上传结果，或事务失效后自动重新上传。
- 插件卸载/重载之间持久恢复事务。
- 改变现有图片压缩编码格式和文件扩展名策略。
- 在 GitHub 或发布说明中宣称通用竞态已复现、彻底修复或普遍兼容。

## Further Notes

- Attachment Management 0.12.1、提交 `363c9d63a2a66867b774cfee0dac51c60d07e44e` 是固定外部验收基线。
- 该基线没有公开事务 ID、完成事件、回调或可等待的整体 Promise；1000ms create 过滤和 500ms Notice debounce 均不是完成信号。
- 仓库中已确认的 Issue #36 生命周期所有权设计文档是设计事实来源。行为落地时必须同步 canonical 架构、本地工作流、设置/UI、图床、开发和领域语言文档。
- `ready-for-agent` 表示 Spec 已准备好供后续 Agent 实施，不代表本轮已经开始修改实现。真实桌面验收矩阵通过前，进度必须标记为部分实施。
